更新紀錄

GrokMediaDownloader 在 Chrome 線上應用程式商店發布的每個版本，由新到舊排列。日期為該版本的建置日，商店上架通常會在幾天內跟進。

Issue 編號指的是公開 GitHub 儲存庫上的回報。

v2.6.0

2026-10-26 功能更新

授權啟用改走自家伺服器，既有金鑰照常使用

2.6.0 唯一的功能變更是 PRO 金鑰的啟用方式；下載、HD 升級、Story Mode 與 Video Gen Queue 都沒有變。這也是 2.5.6 之後第一個上架商店的版本，因此一併帶入下方列出的 2.5.7「Delete Old」變更。

  • 既有金鑰不需要任何動作。已啟用的裝置繼續有效；換新電腦或重灌後，輸入當初 email 收到的同一把金鑰即可。啟用現在改向 Kario 自家的授權伺服器；若該伺服器暫時連不上，擴充功能會自動改走原本的 Lemon Squeezy 啟用路徑。
  • 裝置名額算得更合理。每把金鑰 3 台裝置。擴充功能會在 Chrome 同步儲存空間保存一個固定的裝置 id，同一台電腦重灌不再多吃一個名額，移除擴充功能時會自動釋放名額。彈出視窗的授權區塊會顯示遮罩後的金鑰與「裝置：n / 3」。同一個 Google 帳號同步的多個 Chrome 設定檔共用一個名額；關閉同步的使用者重灌後會拿到新的裝置 id。
  • 六個語系的啟用錯誤訊息都更明確。金鑰無效、屬於其他產品、裝置數已滿（顯示 n / 3）、因退款或撤銷而停用、伺服器連不上，各有專屬說明。產品檢查改在消耗名額之前進行。
  • 接受新的 GMD-XXXX-XXXX-XXXX-XXXX 金鑰格式，原有的 UUID 金鑰同樣有效。
  • 不新增任何權限。授權伺服器透過 CORS 呼叫，更新時 Chrome 不會跳出重新授權提示。繁體中文介面改用「啟用」取代「激活」。

同時包含（2.5.7 的變更，未另行上架）：

  • Delete Old 改讀新的媒體庫。它原本掃描 Grok 舊的「收藏」清單，而該清單自 2026 年 7 月起不再收到新媒體，所以選最近的日期範圍會得到「範圍內沒有項目」。現在改掃描與整庫下載相同的媒體庫，只列出生成的媒體，不會動到上傳的圖片。刪除改用 Grok「已儲存」頁面自己的呼叫：從「已儲存」移除就是永久刪除，貼文會一併刪除。
  • 改名並簡化。「Remove Old」改為「Delete Old」、「Bulk Remove」改為「Bulk Delete」，名稱直接說明這是刪除。移除「Batch Select & Delete」、「Remove All」、「Last N hours」與「Also delete posts」勾選框：Grok「已儲存」頁面本身就有「選取 → 刪除」，其餘選項不是重複就是容易誤刪。Delete Old 現在只有日期範圍（From 與 To 至少填一個）。

更新後：到 chrome://extensions 重新載入擴充功能，並重新整理已開啟的 Grok 分頁。既有用戶不需重新啟用；若彈出視窗仍顯示舊版號，請重新啟動瀏覽器。

v2.5.6

2026-09-14 修正

標籤內容恢復完整，檔名重新帶有提示詞

修正了兩個根本原因，都出在 Grok 那一端。內容與 2.5.5 相同：2.5.5 因隨附的第三方檔案（從未被執行）含有 CDN 位址，未獲 Chrome 線上應用程式商店發布；2.5.6 已移除該檔案。

  • 標籤下載只抓到一個檔案（issue #13）。 Grok 8 月的標籤遷移在新舊兩個方向都不完整：新的 collection API 只有少數歷史項目，舊的 folder API 才有完整歷史，且兩邊各有對方缺少的標籤。標籤清單與標籤內容現在一律是兩個 API 的聯集；原本只抓到 2 筆的標籤，現在可抓到 233 筆。
  • 檔名、資料夾名稱與 metadata.json 沒有提示詞。 自 9 月起，Grok 不再隨媒體清單送出提示詞。現在改從生成該項目的對話取回提示詞（影片使用自己的動畫提示詞，沒有時借用來源圖片的提示詞），並具備重試、斷路器與持久化快取：整庫重新產生清單在第二次執行時由 129 秒降到 10 秒。
  • 只有在檔名或 metadata 設定需要時才會取回提示詞；變更這些設定後，彈出視窗會提示您重新產生清單。
  • metadata.json 會記錄 userId；影片檔名與清單一致，包含短 ID 尾碼；標籤來源部分失敗時會標記為部分結果，而不是回報成功。

已在真實瀏覽器完成端對端驗證：61 個檔案的標籤下載，以及 206 個檔案的整庫 7 天下載，並與 Grok API 逐一比對每個檔案。

v2.5.4

2026-09-03 修正

較舊的標籤與完整的標籤內容

標籤清單可能漏掉較舊的標籤，標籤內容也可能在第一頁之後就停止。

  • 兩種請求現在都使用與 Grok 官方網頁相同的參數，並讀取所有分頁。
  • 若中途某一頁失敗，已取得的項目會保留下來，而不是整批捨棄。

v2.5.3

2026-08-31 修正

標籤分頁與掃描診斷

針對標籤數量多的帳號，延續 2.5.2 的後續修正。

  • 修正標籤清單與標籤內容的分頁。
  • 在系統日誌中記錄完整的掃描診斷資訊，以追查「只有最後一支影片被升級」的回報。

v2.5.2

2026-08-22 修正

新建立的標籤重新出現

Grok 將標籤改建在資產模型上（collection），舊的 folder API 不再更新，因此變更後建立的標籤擴充功能都看不到。

  • 標籤清單與標籤下載改用 Grok 目前的 API，尚未遷移的帳號會自動退回舊 API。
  • 標籤下載也支援以提示詞命名檔案，與整庫來源相同。
  • 每一次 HD 升級的回應都會寫入系統日誌，以便診斷。

v2.5.1

2026-08 修正

預設下載來源失效，因此改換

以實際帳號實測，媒體庫最新的 30 個項目中有 11 個不在收藏清單裡，而 Grok 自己的 Saved 頁面也已完全不再呼叫該端點。

  • 預設來源改為整庫（「所有生成媒體」）；已自行選擇來源的使用者會保留原本的選擇。
  • 下載來源選擇器對所有人免費開放：不該有人被困在看不到自己媒體的來源上。
  • 免費版可掃描整庫最近 7 天的內容。
  • 在選用舊來源、找不到任何項目，以及 HD 升級回報沒有可升級的項目時，都會顯示明確的提示。

v2.5.0

2026-07-26 功能更新

適配 Grok 新媒體後端：整庫下載與 1080p

Grok 在 2026 年 7 月改用「對話 + 資產」後端，舊版本因此看不到新生成的媒體。此版本（同時包含從未發布的 2.4.0 內容）以新 API 重建了偵測機制。

  • 三種下載來源：收藏、標籤，以及新增的整庫（依對話），各自擁有獨立的下載紀錄、可提前停止的日期篩選，以及依對話分組的資料夾。
  • 1080p 成為獨立的畫質層級：下載時取用可取得的最佳畫質，統計會單獨列出 1080p，升級一次只往上一個層級（SD → HD、720p/HD → 1080p）。1080p 升級需自行開啟，若帳號沒有權限會立即停止。
  • 整庫 HD 升級，不再只限收藏；確認前會顯示畫質分布，掃描期間也有停止按鈕。
  • 命名：圖片檔名使用實際的生成提示詞，影片使用其來源圖片的提示詞，資料夾採用 yyyymmdd_prompt_shortid，「Grok 原生」模式也與文件記載的格式一致。
  • 每次掃描的結果一致；在超過 15,000 個項目的媒體庫上，記憶體用量也維持平穩。
