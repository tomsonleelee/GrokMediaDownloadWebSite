v2.6.0

2026-10-26 機能リリース

ライセンスの有効化が自社サーバー経由に。既存のキーはそのまま使えます

2.6.0で機能面に変わったのはPROキーの有効化方法だけです。ダウンロード、HD Upgrade、Story Mode、Video Gen Queueは変わっていません。2.5.6以降で初めてストアに公開されるバージョンでもあるため、下記の2.5.7「Delete Old」の変更も含まれています。

  • 既存のキーは何もしなくて構いません。有効化済みの端末はそのまま使えます。新しいPCや再インストール後は、メールで受け取った同じキーを入力してください。有効化はKario自身のライセンスサーバーに対して行われ、そのサーバーに接続できない場合は拡張機能が自動的に従来のLemon Squeezyによる有効化に切り替えます。
  • 端末枠の数え方が合理的になりました。1つのキーで3台まで。拡張機能はChromeの同期ストレージに固定の端末IDを保存するため、同じPCへの再インストールで枠を余分に消費しなくなり、拡張機能を削除すると枠が解放されます。ポップアップのライセンス欄にマスクされたキーと「端末：n / 3」が表示されます。同じGoogleアカウントで同期している複数のChromeプロファイルは1つの枠を共有し、同期をオフにしている場合は再インストール後に新しい端末IDになります。
  • 有効化エラーのメッセージが6言語で明確になりました。無効なキー、別製品のキー、端末数の上限（n / 3を表示）、返金や取り消しによる無効化、サーバーに接続できない、それぞれに専用の説明が付きます。製品の確認は枠を消費する前に行われます。
  • 新しいGMD-XXXX-XXXX-XXXX-XXXX形式のキーに対応。従来のUUID形式のキーも引き続き有効です。
  • 新しい権限は追加していません。ライセンスサーバーはCORSで呼び出すため、更新時にChromeが再承認を求めることはありません。

同時に含まれる変更（2.5.7、単独では公開されていません）：

  • Delete Oldが新しいメディアライブラリを読むようになりました。以前はGrokの古い「お気に入り」一覧を走査していましたが、その一覧は2026年7月以降新しいメディアを受け取らなくなったため、最近の日付範囲を選ぶと「範囲内に項目なし」になっていました。現在はライブラリ全体ダウンロードと同じライブラリを走査し、生成されたメディアだけを対象にします（アップロードした画像には触れません）。削除にはGrok自身の「保存済み」ページが使う呼び出しを用います。「保存済み」から外すことは完全な削除で、投稿も一緒に削除されます。
  • 名称変更と簡素化。「Remove Old」は「Delete Old」、「Bulk Remove」は「Bulk Delete」に改名し、削除であることを名前で示すようにしました。「Batch Select & Delete」「Remove All」「Last N hours」「Also delete posts」チェックボックスは削除しました。Grokの「保存済み」ページ自体に「選択 → 削除」があり、他の選択肢は重複か誤削除を招くものだったためです。Delete Oldは日付範囲（FromとToの少なくとも一方）だけを指定します。

更新後：chrome://extensions で拡張機能を再読み込みし、開いているGrokのタブを更新してください。既存ユーザーの再有効化は不要です。ポップアップに古いバージョン番号が表示され続ける場合はブラウザを再起動してください。

v2.5.6

2026-09-14 修正

タグが完全に戻り、ファイル名にプロンプトが戻りました

いずれもGrok側の変更に起因する2つの根本原因を修正しました。内容は2.5.5と同じです。2.5.5は、同梱していた（一度も実行されない）サードパーティ製ファイルがCDNを参照していたためChromeウェブストアで公開されず、2.5.6ではそのファイルを削除しました。

  • タグ別ダウンロードで1ファイルしか取得できない問題（issue #13）。 Grokが8月に行ったタグの移行は、どちらの方向にも不完全です。新しいコレクションAPIには過去の項目がわずかしかなく、履歴は旧フォルダAPIに残っており、しかもそれぞれに相手側にないタグがあります。タグの一覧と中身は両APIの和集合を取るようになり、2件しか返らなかったタグで233件が取得できるようになりました。
  • ファイル名・フォルダ名・metadata.jsonにプロンプトが入らない問題。 9月以降、Grokはメディア一覧にプロンプトを含めなくなりました。現在は、その項目を生成した会話からプロンプトを復元します（動画はアニメーション用プロンプトを使うか、元画像のプロンプトを借用します）。リトライ、サーキットブレーカー、永続キャッシュを備えており、ライブラリ全体のリスト再生成は2回目で129秒から10秒に短縮されました。
  • プロンプトは、ファイル名やメタデータの設定で必要な場合にのみ取得します。これらの設定を変更すると、ポップアップでリストの再生成を促します。
  • metadata.jsonにuserIdを記録するようになりました。動画のファイル名は短縮IDの接尾辞も含めてリストと一致します。一部だけ失敗したタグソースは、成功と報告せず「一部のみ」と表示します。

実際のブラウザでエンドツーエンドに検証済みです。61ファイルのタグ別ダウンロードと、206ファイルの直近7日間のライブラリ全体ダウンロードを、Grok APIと1ファイルずつ照合しました。

v2.5.1

2026-08 修正

既定のダウンロードソースが壊れていたため変更しました

実際のアカウントで計測したところ、ライブラリの最新30項目のうち11項目がお気に入りの一覧に含まれていませんでした。さらに、Grok自身の「保存済み」ページはそのエンドポイントをまったく呼び出さなくなっています。

  • 既定のソースをライブラリ全体（「すべての生成メディア」）に変更しました。すでにソースを選んでいたユーザーはその選択がそのまま維持されます。

  • 旧ソースが選択されているとき、何も見つからないとき、HDアップグレードの対象がないときに、分かりやすいヒントを表示します。

v2.5.0

2026-07-26 機能リリース

Grokの新しいメディアバックエンドに対応：ライブラリ全体ダウンロードと1080p

Grokは2026年7月に会話とアセットを基盤とするバックエンドへ移行し、旧バージョンでは新しいメディアを検出できなくなりました。このリリース（未公開に終わった2.4.0の内容も含みます）では、新しいAPIに基づいて検出処理を作り直しました。

  • 3つのダウンロードソース： お気に入り、タグ、そして新しい会話別のライブラリ全体。それぞれに独立したダウンロード履歴、早期停止付きの日付フィルター、会話ごとのフォルダを備えています。
  • 1080pを独立した品質階層に： ダウンロードは利用可能な最高画質を取得し、統計では1080pを別枠で表示します。アップグレードは1段階ずつ行います（SD → HD、720p/HD → 1080p）。1080pへのアップグレードはオプトイン方式で、アカウントに権限がない場合はすぐに停止します。
  • ライブラリ全体のHDアップグレード：お気に入りだけでなくライブラリ全体が対象です。確定前に画質の内訳を表示し、スキャン中は停止ボタンも使えます。
  • 命名： 画像のファイル名には実際の生成プロンプトを、動画には元画像のプロンプトを使い、フォルダ名はyyyymmdd_prompt_shortid形式になります。「Grokネイティブ」モードも説明どおりの形式になりました。
  • スキャン結果は実行ごとにぶれなくなり、15,000項目を超えるライブラリでもメモリ使用量は増え続けません。
