Changelog

Every Chrome Web Store release of GrokMediaDownloader, newest first. Dates are the day the version was built; the store listing usually follows within a few days.

Issue numbers refer to reports on the public GitHub repository. The 2.6.0 release notes will appear here when that version is live on the Chrome Web Store.

v2.5.6

2026-09-14 Fix

Tags come back complete, prompts come back into filenames

Two root causes fixed, both on Grok's side of the fence. Same content as 2.5.5, which the Chrome Web Store did not publish because a bundled (never executed) third-party file referenced a CDN; 2.5.6 removes that file.

  • Tag download returned one file (issue #13). Grok's August tag migration is incomplete in both directions: the new collection API holds few historical items, the old folder API holds the history, and each has tags the other lacks. Tag lists and tag contents are now the union of both APIs; a tag that returned 2 items now returns 233.
  • No prompt in filenames, folder names or metadata.json. Since September Grok no longer sends the prompt with the media list. The prompt is now recovered from the conversation that generated the item (videos use their animation prompt or borrow the source image's), with retries, a circuit breaker, and a persistent cache: a whole-library regenerate went from 129 s to 10 s on the second run.
  • Prompts are only fetched when your filename or metadata settings need them; the popup asks you to regenerate the list after you change those settings.
  • metadata.json records userId; video filenames match the list, including the short-ID suffix; a tag source that half-fails is marked partial instead of reported as success.

Verified end to end in a real browser: a 61-file tag download and a 206-file seven-day whole-library download, compared file by file against the Grok API.

v2.5.4

2026-09-03 Fix

Older tags and full tag contents

The tag list could miss older tags and tag contents could stop after the first page.

  • Both requests now use the same parameters as Grok's own web app and read every page.
  • If one page fails mid-way, the items already fetched are kept instead of the whole batch being discarded.

v2.5.3

2026-08-31 Fix

Tag pagination and scan diagnostics

Follow-up to 2.5.2 for accounts with many tags.

  • Tag list and tag content pagination fixes.
  • Full scan diagnostics in the system log to track down "only the last video was upgraded" reports.

v2.5.2

2026-08-22 Fix

Newly created tags appear again

Grok rebuilt tags on its asset model as collections; the old folder API stopped updating, so tags created after the change were invisible to the extension.

  • Tag list and tag download switched to Grok's current API, with automatic fallback to the old one for accounts not yet migrated.
  • Tag downloads gained prompt-based filenames, like the whole-library source.
  • Every HD upgrade response is written to the system log for diagnosis.

v2.5.1

2026-08 Fix

The default download source was broken, so it changed

Measured on a live account, 11 of the 30 newest library items were missing from the Favorites list, and Grok's own Saved page no longer calls that endpoint at all.

  • Default source is now the whole library ("All Generated Media"); users who had already picked a source keep their choice.
  • The download source selector is free for everyone: nobody should be stuck on a source that cannot see their own media.
  • The free version can scan the whole library for the last 7 days.
  • Clear hints when the old source is selected, when nothing is found, and when HD upgrade reports nothing to upgrade.

v2.5.0

2026-07-26 Feature release

Adapted to Grok's new media backend: whole-library download and 1080p

Grok moved to a conversation-and-asset backend in July 2026 and older versions could no longer see new media. This release (which also ships the never-published 2.4.0 work) rebuilds detection on the new API.

  • Three download sources: Favorites, Tags, and the new whole library by conversation, each with its own download history, date filters with early stop, and per-conversation folders.
  • 1080p as its own quality tier: downloads take the best available quality, statistics list 1080p separately, and upgrades move one tier at a time (SD → HD, 720p/HD → 1080p). 1080p upgrades are opt-in and stop immediately if the account has no access.
  • HD upgrade for the whole library, not just favorites, with a quality breakdown before you confirm and a stop button during the scan.
  • Naming: image filenames use the real generation prompt, videos use their source image's prompt, folders use yyyymmdd_prompt_shortid, and the "Grok native" mode matches its documented format.
  • Scan results are stable between runs; memory stays flat on libraries of 15,000+ items.
