전체 라이브러리 다운로드 작동 방식

네 단계, 각 단계마다 진행 상황이 보입니다.

1

소스 선택

Grok Imagine 페이지에서 확장 프로그램을 열고 다운로드 소스 선택기에서 "📦 모든 생성 미디어(대화별)"를 선택합니다. 필요하면 최근 N시간 구간이나 날짜 범위를 설정하세요.

2

목록 생성

확장 프로그램이 최신순으로 라이브러리를 스캔하고, 각 동영상의 품질 계층을 확인하며, 대화 폴더를 준비합니다. 스캔 중, 동영상 품질 확인 N/M, 폴더 준비 N/M 등 각 단계의 진행 상황이 보고됩니다.

3

요약 확인

요약에는 다운로드 예정 및 완료된 이미지와 동영상 수가 표시되며, 동영상은 1080p, HD, 720p, SD로 나뉘어 표시되므로 무엇을 가져올지 정확히 알 수 있습니다.

4

다운로드 및 보관

파일은 대화별 폴더에 프롬프트 기반 이름으로 다운로드됩니다. 중단된 다운로드는 기록되므로 재시도 시 누락된 것만 가져오며 완료된 파일을 다시 받지 않습니다.

기술 하이라이트

적응형 스로틀링과 429 백오프

스캔 속도가 서버 응답에 맞춰 조정되며 속도 제한 백오프를 갖췄습니다. 8,000개 이상의 라이브러리도 중간에 끊기지 않고 끝까지 스캔할 수 있습니다.

동시 품질 확인

동영상 품질을 제한된 동시성과 실시간 카운터로 확인해, 기존에 몇 분 걸리던 단계를 약 1분으로 단축했습니다.

실제 프롬프트 파일명

이미지는 자체 생성 프롬프트를 사용하고, 동영상은 원본 이미지의 프롬프트를 이어받습니다. Grok이 동영상 에셋 자체에는 프롬프트를 저장하지 않기 때문입니다.

대화 제목 일괄 조회

실제로 필요한 대화의 제목만 일괄로 가져옵니다. 전체 대화 목록을 페이지 단위로 훑지 않습니다.

자주 묻는 질문

전체 라이브러리 다운로드에 대해 알아야 할 모든 것

전체 라이브러리 다운로드란 무엇인가요?

전체 라이브러리 다운로드는 GrokMediaDownloader v2.5에서 새로 추가된 다운로드 소스로, Grok Imagine 라이브러리에 있는 모든 생성 이미지와 동영상을 가져옵니다. 즐겨찾기로 표시했거나 태그로 분류한 항목에만 국한되지 않습니다. 확장 프로그램 팝업에서는 기존의 즐겨찾기, 태그와 나란히 다운로드 소스 선택기에 "📦 모든 생성 미디어(대화별)"로 표시됩니다. 선별된 일부가 아니라 전체 에셋 목록을 읽기 때문에, 지금까지 생성한 모든 것을 로컬에 완전히 보관하고 싶을 때 알맞은 선택입니다. 파일은 대화당 하나의 폴더로 묶이므로, 스레드를 시작한 이미지와 그로부터 생성된 동영상이 평평한 다운로드 디렉터리에 흩어지지 않고 한곳에 모입니다.

즐겨찾기·태그 다운로드와 어떻게 다른가요?

세 가지 소스는 각기 다른 필요에 대응하며 서로 완전히 독립적입니다. 즐겨찾기는 Grok에서 좋아요를 누른 항목만 다운로드하므로 대상이 작고 선별된 상태로 유지됩니다. 태그는 특정 Grok 태그나 폴더에 분류된 모든 것을 다운로드하고 tags/{tagName}/ 아래에 정리합니다. 전체 라이브러리는 두 필터를 모두 무시하고 생성 라이브러리 전체를 대상으로 하며, 대신 대화별로 출력을 정리합니다. 중요한 점은 각 소스가 자체 다운로드 기록을 유지한다는 것입니다. 따라서 전체 라이브러리를 다운로드해도 즐겨찾기가 이미 다운로드됨으로 표시되지 않으며 그 반대도 마찬가지입니다. 세 가지를 오래 병행해 사용해도 한쪽이 다른 쪽의 중복 제거 기록을 오염시키지 않습니다. 이는 v2.5 이전에 흔한 혼란의 원인이었습니다.

폴더와 파일 이름은 어떻게 정해지나요?

각 대화가 하나의 폴더가 되며 yyyymmdd_프롬프트_짧은ID 패턴으로 이름이 지정됩니다. 대화에 제목이 없으면 확장 프로그램은 폴더를 "untitled"로 표시하는 대신 해당 대화의 프롬프트를 사용합니다. 몇 달 뒤에 다시 열어봐도 폴더 이름이 의미를 유지합니다. 이미지 파일명은 해당 이미지에 기록된 실제 생성 프롬프트를 사용하고, 동영상 파일명은 원본 이미지의 프롬프트를 사용합니다. Grok이 동영상 에셋 자체에는 프롬프트를 저장하지 않기 때문입니다. 기계적인 이름을 선호한다면 "Grok 기본" 파일명 모드가 grok_image_YYYYMMDD_id를 생성합니다. 파일명은 목록에 고정되지 않고 다운로드 시점에 생성되므로, 파일명 형식을 바꿔도 목록을 다시 생성할 필요가 없습니다.

새로 생성한 Grok 미디어가 왜 감지되지 않나요?

2026년 7월 Grok은 새로운 "대화 + 에셋" 미디어 백엔드로 전환했습니다. 이전 확장 프로그램 버전이 의존하던 엔드포인트는 더 이상 Saved 및 미디어 라이브러리 화면을 지원하지 않으므로, v2.5.0 이전 버전은 전환 이후 생성된 이미지와 동영상을 볼 수 없습니다. GrokMediaDownloader v2.5.0은 새 백엔드에 대한 완전한 대응이며 새로 생성된 미디어의 감지를 복구합니다. 업데이트 후 chrome://extensions를 열어 확장 프로그램을 다시 로드하고 Grok 탭을 새로 고치세요. 다운로드 목록도 한 번 다시 생성해야 합니다. 프롬프트 기반 파일명과 새로운 대화 폴더 규칙은 "목록 생성" 단계에서 기록되며, 이전 버전으로 만든 목록에는 소급 적용되지 않기 때문입니다.

전체 라이브러리 다운로드를 날짜로 필터링할 수 있나요?

네. 전체 라이브러리 소스는 다른 소스와 동일한 날짜 필터를 지원하며, 최근 N시간 구간과 명시적인 날짜 범위를 모두 다룹니다. 스캔은 최신순으로 라이브러리를 따라가다가 선택한 구간의 끝을 지나면 조기에 중단합니다. 따라서 날짜로 필터링할 때 결과를 보기 위해 라이브러리 전체를 다 훑을 필요가 없습니다. 이는 대규모 계정에서 특히 중요합니다. 적응형 스로틀링 및 429 속도 제한 백오프와 결합하면 8,000개 이상의 에셋을 가진 라이브러리도 끝까지 스캔할 수 있지만, 좁은 날짜 필터는 훨씬 빨리 끝납니다. "목록 생성" 버튼은 스캔, 동영상 품질 확인, 폴더 준비의 각 단계별 진행 상황을 보고하므로 지금 어느 단계가 실행 중인지 알 수 있습니다.

v2.5의 1080p 지원은 무엇을 더해주나요?

v2.5는 확장 프로그램 전반에서 1080p를 독립된 품질 계층으로 인식합니다. 다운로드는 사용 가능한 최고 품질을 자동으로 선택하며, 1080p를 HD보다, HD를 원본 파일보다 우선합니다. 스캔 통계는 모든 것을 SD와 HD로 뭉뚱그리지 않고 SD, HD/720p, 1080p에 각각 몇 개의 동영상이 있는지 구분해 보여줍니다. 업그레이드 기능은 이제 한 번에 한 단계씩, SD에서 HD로, 720p 또는 HD에서 1080p로 끌어올릴 수 있습니다. 1080p 업그레이드에는 유료 Grok 플랜, 구체적으로 SuperGrok Heavy가 필요하므로 기본적으로 꺼져 있는 명시적 선택 체크박스 뒤에 있습니다. 체크하지 않으면 확장 프로그램은 1080p 요청을 전혀 보내지 않습니다.

이전에는 업그레이드 스캔을 반복할 때마다 결과가 달랐던 이유는 무엇인가요?

Grok 서버는 갓 생성된 동영상에 대해 HD 미디어 URL을 일관되지 않게 반환합니다. 같은 동영상을 몇 초 안에 두 번 조회하면 한 번은 해당 필드가 오고 다음에는 누락될 수 있었습니다. 해상도 필드 자체는 안정적인데도 말이죠. 그래서 같은 동영상이 어떤 스캔에서는 SD, 다음에는 HD로 보였고, "최근 N시간 업그레이드"를 반복할 때마다 다른 결과가 나왔습니다. v2.5는 업그레이드 판단 전용 품질 기억을 추가해 각 동영상에서 확인된 최고 품질을 기록하고, 이후 조회가 불완전하게 돌아와도 등급을 낮추지 않습니다. 기록에는 30일 유효 기간과 개수 상한이 있으며, 기억한 URL이 유효하지 않은 것으로 밝혀지면 자동으로 삭제됩니다.
